# Реализация основного кика в v4.94

После сообщения пользователя о неработающем физическом sweep эта ветка больше не применяется в основном кике. Основной маршрут Main теперь вызывает SourceContact. Это API вызов, а не подтверждение серверного удара; наблюдаемый Ragdolled хранится отдельно и только читается.

В supplied source подготовка палетки расположена на строках 1773–1806: отключение столкновений/запросов, Massless, AngularVelocity=(5000,0,5000), SoundPart.Size=(6,2,6), подъём к Y=10000 и начальное размещение на Y=1000. В Astral angular constraint дополнительно получает MaxTorque=math.huge: одного задания угловой скорости недостаточно при нулевом лимите torque. При one-shot ragdoll этот profile снимается, чтобы два подъёмных mover не работали одновременно.

Кик source на строках 5990–6035 вызывает касание root этой палеткой и затем Faster/Stronger ownership sequences. В Astral восстановлена эта связка, удалено ожидание физического sweep и конечной позиции hold, добавлена балансировка begin/end. Native CanTouch root временно включается и восстанавливается; source ошибка отключения touch непосредственно перед вызовом не копируется. Владение подготовленной доской не подтверждается заново по marker после каждого намеренного target Grab.

Позиция hold остаётся точно над локальным игроком по запросу пользователя; BP.D=100 соответствует source, дополнительный gyro из прежнего controller не создаётся. Source обнуляет скорости целевых частей; Astral выполняет это только для частей с подтверждённой local physics ownership, не меняя native welds/motors/constraints или массу персонажа. Одного наличия чужого PartOwner для capture по-прежнему недостаточно.

Устранены два независимых источника лишних палеток: Native и Warm используют одну supply transaction, а для этой transaction больше не вызывается общий SpawnToy с повторным RPC на каждом кадре foreign plot. Частичная модель сохраняется до streaming частей; timeout без известного отказа не отправляет новый RPC. Поздний результат после остановки сохраняется для повторного использования, после unload уничтожается. Отдельный ограниченный таймер освобождает глобальный Spawning flag, не теряя ожидаемую transaction.

Настройки физической серии сняты с основного кика, поскольку больше не применяются; Faster/Normal, высота, ragdoll switch, retry rate и полный настраиваемый Loop MS остаются. Увеличение частоты запросов не подменяет эти изменения реализации.

Проверки CLI/mocks подтверждают пути выполнения и lifecycle, а не серверное принятие ударов или время кика. Source не предоставляет интерфейса, который сообщает «до кика осталось N ударов», не содержит доказательства кика менее чем за 10 секунд и не предоставляет серверной блокировки чужого grab. Отнесённая палетка остаётся обычной реплицируемой игрушкой.

Ниже сохранён разбор источника методов. Его сведения о переносе относятся к v4.92, а текущий основной маршрут описан выше.

# Перенос методов TheWorst в Astral v4.92

Приложенный message-5.txt совпадает с ранее изученным файлом: 8 913 строк; SHA-256 после нормализации переводов строк — `0358b911961945100814366070ce49f1e7066532be22c274a0ff2078bd519b02`. Загрузчик и игровой код вложения не выполнялись.

Источник: Ownership mode и Kick на строках 5755–6053. Название Normal добавлено в Astral для исходного Solo Stronger; отдельного Normal в этой версии TheWorst нет.

| Метод | Перенесённое действие |
| --- | --- |
| Faster | После подтверждённого первичного capture — исходный ordered Grab/Release refresh за такт |
| Normal / Stronger | G → wait → G/R/G → wait → G/G → wait → G/R; шесть ownership requests и два release |
| Несколько целей | Круг радиусом 7 из исходного Multi, без растущего вертикального стека за границей grab range |
| Рагдолл | Native firetouchinterest с paired begin/end; физическая палетка при отсутствии executor API |
| Blobman | Source delay в миллисекундах 0–1000, применённый к полному Grab/Drop циклу |
| Anti Blobman Aura Grab | Ownership request root сидящего на Blobman игрока в пределах 19 studs (строки 2936–2968) |

Исправления при переносе:

1. Условие source capture на строках 5917–5921 принимало наличие любого PartOwner, даже чужого, за причину закончить захват. Проверяется принадлежность именно локальному игроку и физическое владение.
2. Source Solo отключал CanTouch у root прямо перед firetouchinterest (строки 5985–5996). При переносе принимающая часть не отключается.
3. Для повторных касаний добавлен конец контакта в следующем кадре и отмена открытого контакта; локальное касание не называется серверным kick acknowledgement.
4. Первичный Grab не отпускается в том же такте до capture; последующие Faster refresh сохраняют source order. Native requests имеют проверку диапазона и конечного CFrame.
5. При смене selection/защиты/персонажа старый target snapshot не создаёт сессию заново. Оба переключателя используют один controller, без одновременно работающего Circle + Lag.

Anti Kick в Worst продолжает использовать ownership reacquisition и StickyPartEvent. В нашей версии исправлен собственный blocking gate на executor physics metadata и отменён отложенный Grab после появления реального weld. Сохранить настоящий weld безопаснее, чем повторно Grab-ать уже прикреплённую игрушку ради метаданных: тот же Grab используется Unstick для снятия предметов. Это исправление кода, а не доказательство иммунитета к чужой ауре.

Source Anti food (5632–5698) использует HoldItemRemoteFunction и DropItemRemoteFunction с CFrame/velocity. Наша подтверждаемая схема сохранена и переиспользована для всех Break Holdable callers. Локальное удаление DropItemRemoteFunction убрано; небезопасные source параметры далеко за картой не копировались.

В этой версии source Anti explosion только присваивает флаг на строке 3231 и нигде его не использует. Astral поэтому использует отдельный native removal только ног с отменой и восстановлением guards. Рабочего Freeze PCLD в приложении по-прежнему нет.

Проверено поведение исходников и engine mocks. Время кика, серверное принятие ударов, реальная неотрывность и FPS в Roblox не измерялись.
