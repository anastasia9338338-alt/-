# Astral v4.92

[Скачать ZIP](https://github.com/anastasia9338338-alt/-/raw/refs/heads/codex/astral-v4.92-source-modes-defense-shop/astral.zip?download=1) · [Lua отдельно](https://github.com/anastasia9338338-alt/-/raw/refs/heads/codex/astral-v4.92-source-modes-defense-shop/astral.lua?download=1)

Сначала Settings → Unload astral, затем выполнить новый Lua.

Основной ownership kick использует методы из приложенного TheWorst с выбором **Faster / Normal** в Kick Settings. Normal соответствует Solo Stronger в исходнике. Оба переключателя, Enable Kick и Enable Server Kick, используют этот контроллер; прежний Circle + Lag одновременно не запускается. Первичное получение владения подтверждается marker и физическим ownership. Далее Faster выполняет исходный ordered Grab/Release refresh, Normal — исходную последовательность шести Grab и двух Release за четыре такта. Для нескольких целей используется круг радиусом 7, чтобы цели оставались в пределах native ownership range. Loop MS остаётся дополнительным ограничителем полного цикла.

Исправлены ошибки исходника: чужой PartOwner больше не считается успешным захватом, CanTouch принимающей части не выключается перед ударом, парные begin/end контакты не перекрываются, поздняя отмена не создаёт новую сессию для снятого с выбора игрока. При наличии firetouchinterest применяется исходный touch-метод. Если его нет, используется существующая физическая палетка, включая одиночное начальное воздействие до устойчивого удержания. Успешный серверный кик и его время не выводятся из локального touch-события.

В настройках Blobman Kick находится **Blobman Kick Delay: 0–1000 ms**. Это задержка полного цикла, не число ударов в секунду; 0 убирает дополнительную задержку, а действия всё равно разделены игровыми кадрами. **Defense → Blobman → Anti Blobman Aura Grab** использует метод Worst: запрос ownership на root сидящего на Blobman игрока в пределах 19 studs. Банан для этой функции не используется; Banana Aura Blobman остаётся отдельной функцией.

Anti Kick больше не блокирует StickyPartEvent из-за задержки локальной проверки physics ownership. Настоящее крепление проверяется по обеим сторонам оригинального StickyWeld. Если оно уже появилось, отложенный Grab отменяется: иначе проверка здоровья сама могла снять защитную игрушку. Удалён дублирующий большой inline-цикл; текущий hitbox и персонаж повторно проверяются после ожиданий. Сам Unstick не имеет добавленных исключений и сохраняет своё исходное поведение. Неотрывность под чужой аурой не обещается.

Общий Break Holdable теперь использует тот же подтверждаемый Hold → Drop, что Remove Food, и не уничтожает DropItemRemoteFunction локально. Это исправляет повторные попытки для еды, удерживаемых предметов и других существующих callers. Нельзя принимать возврат remote за доказательство отсоединения: проверяется Attachment1.

**Anti Explosion — Legs** — отдельная выключенная по умолчанию функция, убирающая только ноги собственным native ragdoll/limb методом. Голова, руки и тело не передаются удалению. На время операции AntiGrab/AntiExplore уступают управление и затем восстанавливаются. Ноги возвращаются при respawn. В приложенном исходнике Anti explosion содержит только переключатель с присваиванием флага, без использующего его обработчика; готовую реализацию из него переносить было нечего.

Магазин сохраняет прежний размер, цвета, картинки и callbacks. Дерево GUI кешируется до структурного изменения, обход не спускается внутрь 3D-моделей preview. Повторно открытая вкладка использует готовое оформление; ячейки оформляются заново только при изменении или размере. Закрытие скрывает оформление, полное восстановление native свойств происходит при отключении стиля/unload. Изменение счётчика и стриминг частей preview не переоформляют всю коллекцию. Это оптимизация работы скрипта; живые FPS Roblox здесь не измерялись.

Точный Lua и ZIP прошли компиляцию, проверку dependencies/API и полные регрессионные сценарии, включая native аргументы, подтверждение захвата/отсоединения, отмену, respawn/unload, оба source kick метода и кеш магазина.
